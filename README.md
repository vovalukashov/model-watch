# model-watch

Git-scraping для каталогов моделей: раз в 10 минут GitHub Actions скачивает
конфиги и списки моделей, кладёт снимок в `data/` и коммитит. Разница — какие model id
появились и какие исчезли — остаётся в истории коммитов, а в Telegram приходит, только когда
в ней есть признаки новых моделей. Ровно так и появился скриншот с
`gpt-6-sol / gpt-6-luna / gpt-6-astra-minor`.

Для базового режима зависимостей нет: Python 3.10+ и git. AI-сводке нужен пакет `anthropic` —
он в `requirements.txt`, Actions ставит его сам.

## Запуск за 10 минут

1. Создай **публичный** репозиторий и залей файлы. Публичный — потому что в нём
   минуты Actions бесплатны без ограничений; ничего секретного в репозитории нет,
   ключи живут в Secrets. Быстрее всего через gh CLI из папки проекта:

   ```bash
   git init && git add . && git commit -m "init"
   gh repo create model-watch --public --source=. --push
   ```
2. Заведи бота у @BotFather, напиши ему любое сообщение и возьми `chat.id`
   из `https://api.telegram.org/bot<TOKEN>/getUpdates`
   (для канала — добавь бота админом и используй id канала вида `-100…`).
3. Секреты — через веб (Settings → Secrets and variables → Actions) или одной
   командой на каждый:

   ```bash
   gh secret set TELEGRAM_BOT_TOKEN
   gh secret set TELEGRAM_CHAT_ID
   gh secret set OPENAI_API_KEY      # по желанию
   gh secret set ANTHROPIC_API_KEY   # по желанию
   gh secret set APIFY_TOKEN         # по желанию: chatgpt.com и claude.ai через Apify
   ```

   С ключами провайдеров начнут отслеживаться и официальные `/v1/models`;
   без них эти два источника просто пропускаются. С токеном Apify добавятся
   `chatgpt-web` и `claude-web` (см. ниже).
4. Первый запуск руками: `gh workflow run model-watch` (или вкладка Actions →
   `model-watch` → Run workflow). Он сделает базовый снимок, закоммитит его
   в `data/` и пришлёт короткое «первый снимок, N id». Дальше — по крону.

Локально: `python watch.py` — без токена печатает отчёт в консоль.

## Как добавить источник

Один объект в `sources.json`:

```json
{
  "name": "vertex-catalog",
  "url": "https://…/models.json",
  "kind": "json",              // json | text
  "extract": "key",            // regex | key | top_keys
  "key": "id",                 // для extract=key
  "pattern": "…",              // для extract=regex; если есть группа — берётся группа 1
  "only": "(?i)gpt|claude",    // необязательный фильтр по извлечённым id
  "lowercase": true,           // привести id к нижнему регистру (GPT-5.5 и gpt-5.5 — одно имя)
  "headers": { "Authorization": "Bearer ${SOME_SECRET}" },
  "keep_full": true,           // хранить ли полный нормализованный снимок в data/<name>.json
  "alert_removed": true        // false для «скользящих» лент вроде Atom-фидов коммитов
}
```

Если в `headers` есть `${VAR}`, а переменной нет в окружении — источник пропускается без ошибки.

Особый `"kind": "apify"` — для сайтов, которые отвечают скрипту 403: вместо `fetch` запускается
актор Apify, а его выдачу разбирает `"extract": "key_list"`. Поля: `"token": "${APIFY_TOKEN}"`,
`"pattern"` (регулярка в синтаксисе JS RegExp — флаг `i` добавляет актор, поэтому `(?i)` писать
нельзя), `"min_interval_hours"` (как часто гонять актор; прогоны стоят денег).

## AI-сводка

Каждое добавленное id скрипт сводит к имени модели (`azure/gpt-5.4-pro-2026-03-05` → `gpt-5-4-pro`)
и сверяет со всем, что источники показывали раньше. Имя, которого не было нигде, помечается 🆕.

- Есть новые имена — модель `xiaomi/mimo-v2.6-flash` (запасная — `anthropic/claude-haiku-4.5`) пишет
  короткую сводку по-русски: что появилось, где и что это скорее всего значит. Сводка идёт первой,
  сырой дифф ниже.
- AI недоступен — новые имена перечислены в заголовке.
- Новых имён нет (копии известных моделей у перепродавцов, режимы вроде `-fast`, удаления) —
  в Telegram ничего не приходит и модель не вызывается. Изменения видны в логе Actions и в истории `data/`.

Ключей нет нигде. Модель вызывается через `ai-proxy/` — функцию на Vercel. Workflow доказывает, кто он,
OIDC-токеном GitHub (`id-token: write`), а прокси идёт в AI Gateway с OIDC-токеном, который ему выдал Vercel.
Прокси пускает только этот репозиторий, ветку `main` и `watch.yml`, только две модели и не больше
4096 токенов на ответ; на проект в AI Gateway стоит бюджет $1 в месяц.

Развернуть прокси: `cd ai-proxy && vercel deploy --prod`, затем его адрес с суффиксом `/api` — в переменную
репозитория `AI_PROXY_URL` (Settings → Secrets and variables → Actions → Variables). Пока переменной нет,
сообщения приходят без сводки.

Токены и цена каждого вызова видны в логе шага «Fetch, extract, diff, notify» строкой `[ai] …`.
Проверить связку GitHub → прокси → модель → Telegram: Actions → model-watch → Run workflow → галочка `ai_selftest`.

## Память и два особых события

`data/seen.tsv` — каждое имя модели, которое хоть один источник когда-либо показывал, и время, когда вотчер увидел
его впервые. Файл только растёт. Новизну 🆕 скрипт считает по нему, поэтому имя, которое выпало из скользящей ленты
коммитов или которое убрали из каталога, при возвращении не выдаётся за новое.

В каталогах новизна считается только по каталогам. Имя, которое раньше мелькало лишь в ленте коммитов, в день
первого появления в каталоге приходит как 🆕 с AI-сводкой: так слив в коде превращается в релиз.

Кроме 🆕, признаками новых моделей считаются ещё два события, и они тоже приходят в Telegram:

- `🫥 убрали` — имя, которое появилось не больше недели назад, пропало из каталога. Так выглядит прибранный слив.
  Событие приходит, даже если другие каталоги имя ещё держат: litellm и models-dev копируют слитые имена за часы и
  почти их не удаляют. В сообщении видно, осталось ли имя где-то ещё. Если каталог оставил вариант имени
  (переименованную копию, модель без `-fast`), это не уборка.
- `↩️ вернулось` — имя, про которое раньше пришло `🫥 убрали`, снова появилось в каталоге. Так выглядит релиз после
  прибранного слива. Старые модели, которые litellm убрал и вернул откатом, этого события не дают: их никто не
  «убирал» свежими.

Каталоги — все источники, кроме лент коммитов (`alert_removed: false`): имена уходят оттуда постоянно, и это ничего не
значит. Старые модели, пропавшие из каталогов (чистка litellm и подобное), в Telegram не приходят: они остаются в
истории `data/`.
Если каталог вернулся пустым или длинный список потерял за одну проверку больше половины, это считается сбоем
скачивания, и `🫥` по нему не приходят: самая большая настоящая чистка пока — 8% id у litellm.
Имена, которые уже были в снимках на момент запуска памяти или пришли с только что подключённым источником, записаны
без времени: когда они появились на самом деле, неизвестно, и событие «убрали» для них не срабатывает.

## Сайты chatgpt.com и claude.ai (Apify)

Напрямую оба сайта отвечают скрипту 403 с проверкой Cloudflare, поэтому их читает актор Apify
(`apify/playwright-scraper`, headless-браузер + residential-прокси). Актор открывает страницу,
собирает URL всех JS-бандлов, скачивает их и ищет регуляркой имена моделей и тарифов — то же, что
исследователи делают руками: так `promax` нашли в коде chatgpt.com за два часа до `PlanType.ts`.
Ловятся три формы строк: model id (`gpt-5.6-sol.access`), раскатка тарифа
(`chatgpt-subscription-complete-pro-max`) и голое имя рядом с `planType:"…"` / `plans.…`.
Найденное ложится в `data/chatgpt-web.json` и `data/claude-web.json` и живёт по общим правилам:
🆕 за новое имя, 🫥 за свежую строку, которую вычистили из бандла.

Настройка: `gh secret set APIFY_TOKEN` (токен — в консоли Apify, Settings → Integrations). Без
секрета оба источника молча пропускаются.

Деньги: прогон одного источника стоит ориентировочно $0.15–0.25 (браузер с 2 ГБ на пару минут —
это копейки, основное — residential-трафик на бандлы, 20–30 МБ за прогон). Читается по одной
странице на сайт: у chatgpt.com это `/pricing` — замеры показали, что страница приложения
не добавляет к ней почти ничего, а HTML без бандлов бесполезен (6 id против 276). С
`min_interval_hours: 24` это ~$9–10 в месяц на оба сайта — вполовину квоты Starter ($19);
на 12 ч счёт удвоится. Время последнего прогона лежит в `data/<name>.apify-state.json`;
неудачный прогон тоже засчитывается, чтобы ошибки не жгли бюджет каждые 10 минут. Если
Cloudflare всё же не пустил, в снимке видно `"blocked": N` и пустые `matches` — источник
молчит до следующего прогона.

## Оговорки

- `PlaygroundConfig.json` у Azure — внутренний файл фронтенда, он может переехать
  или начать отдавать 403. Тогда просто заменишь URL: скрипт при ошибке
  скачивания пропускает источник, остальные работают.
- `chatgpt-plans` читает `PlanType.ts` из репозитория Codex — сгенерированный список тарифов ChatGPT,
  которые знает клиент. Если Codex перенесёт файл, источник начнёт падать с 404, и URL надо будет поменять.
  Сам chatgpt.com, где такие строки видно раньше всего, читается через Apify — см. секцию выше.
- Расписание GitHub Actions на деле срабатывало раз в 3–5 часов вместо 10 минут, поэтому ритм держит
  `tick.yml`. Каждый tick ждёт 10 минут на таймере окружения `tick` (раннер при этом не занят, ожидание
  не тарифицируется), потом запускает `watch.yml` и следующий tick. Расписания в обоих workflow —
  только страховка: перезапускают цепочку, если она оборвётся.
- Если цепочка встала, об этом приходит `⚠️ model-watch: цепочка tick встала` с временем последней проверки.
  Его шлёт запасное расписание `watch.yml`: когда оно срабатывает, скрипт с флагом `--check-chain` смотрит,
  когда цепочка последний раз запускала проверку, и молчит, если это было меньше 30 минут назад. Пока цепочка
  стоит, предупреждение повторяется при каждом срабатывании расписания, то есть раз в несколько часов.
  Перезапуск: Actions → tick → Run workflow. Это единственное сообщение не про модели: без цепочки проверки
  идут раз в несколько часов, и короткие сливы проскочат.
- Таймер живёт в окружении `tick` (Settings → Environments). Если его удалить или обнулить, tick
  заметит, что предыдущий прогон был меньше 5 минут назад, упадёт с ошибкой и не будет крутиться.
- В публичном репозитории минуты Actions не тарифицируются; в приватном на GitHub Free квота
  2 000 минут в месяц, и такой ритм её превысит.
- Если в репозитории 60 дней нет активности, GitHub отключает расписания; цепочку tick это не
  затрагивает, а снимки и так дают активность.
- Строка в конфиге доказывает, что модель готовят к раздаче, а не дату и не характеристики.
